## Apache static deployment

Publish all of `dist/brapci/browser`, including the hidden `.htaccess` file.
`public/.htaccess` is the source rule file and must be retained in future builds.
The HTTPS VirtualHost DocumentRoot must point to the deployed browser directory.
Enable `mod_rewrite` and allow rewrite directives in that directory, for example:

```apache
DocumentRoot /var/www/brapci/dist/brapci/browser
<Directory /var/www/brapci/dist/brapci/browser>
    Options +FollowSymLinks -MultiViews
    AllowOverride FileInfo
    Require all granted
</Directory>
```

Replace the example path with the actual deployment path. On Ubuntu:

```bash
sudo a2enmod rewrite
sudo apache2ctl configtest
sudo systemctl reload apache2
```

Existing files and prerendered directories are served normally. Other frontend
routes (such as `/v/76314`) use `index.csr.html`, or `index.html` when the client
shell is absent. Keep `index.csr.html` in the upload when generated by the build.
The URL remains unchanged, allowing the Angular router to load the requested page.
Missing assets and `/api` or `/auth` endpoints are excluded from the fallback.
Backend endpoints need their own existing server/proxy configuration.

This static deployment renders dynamic pages in the browser. Server-side rendering
requires running the Node server and configuring Apache to proxy to it.
After deployment, open `/v/76314` directly and refresh it to verify routing.
